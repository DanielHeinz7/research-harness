ref: SQ-15
title: Session ledger and the SessionStart injection
bump: patch
plugins:
  - research-harness
---

A session that opens a paper project now starts knowing where the canvas
stands. The `SessionStart` hook reads `research/canvas.md`, runs the mechanical
review, and injects one block under 4 KiB: per-element status with the count of
open proposals, which elements are empty, which hold proposals only, dependency
violations, acceptances whose recorded text hash no longer matches, and the
decisions this session has not been shown yet — followed by the four rules for
writing the canvas. In any repository without a canvas it prints nothing.

The hook fails open by construction. An unparseable canvas, an unreadable file
or a profile the plugin does not ship never stops a prompt: a canvas with no
elements yields no output at all, and an unknown profile is reported as
`profile <id> (not found; dependencies not checked)` so the rest of the summary
still arrives. `hooks/lib/output.js` owns both hook output shapes and the byte
budget, truncating on a code point boundary with a watermark that names the
budget and points at `research-harness status`.

Decisions are injected once. `hooks/lib/ledger.js` keeps the highest sequence
already shown per project and session in a hashed file under
`$RESEARCH_HARNESS_STATE_DIR` (by default `~/.claude/research-harness`) —
outside the repository, because it is a property of the session, not of the
paper. A failed ledger write costs a repeated injection and nothing more.
`summarize()` is exported so the coming `status` subcommand renders the same
summary the session was given instead of a second one that could drift.
