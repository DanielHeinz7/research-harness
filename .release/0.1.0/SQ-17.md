`bin/research-harness.js` is the command behind the three skills. `init` copies
`references/canvas-elements.md` into `research/canvas.md` with the project's own
frontmatter and opens an empty decision log; it refuses to overwrite a canvas
that already exists. `status` prints the same summary the SessionStart hook
injects — it calls `summarize()` from `hooks/inject-state.js` rather than
rendering the state a second time, so the two can never drift. `review` prints
the mechanical half of the review as Markdown.

`accept` is the researcher's path (spec §5.4). It promotes exactly one statement
in one question to `[accepted]` and keeps the evidence tags the researcher put on
it — only the marker changes. It refuses when an element the profile's graph says
this one depends on is not accepted, and it names which element is in which
state. When a question holds more than one candidate it prints the candidates and
asks for `--match`, because guessing which statement the researcher meant would
be the harness accepting on their behalf. On success it appends a `DECISION`
entry to the log carrying the text hash, which is what later binds the
acceptance to the wording it was given for.

Exit codes are 0 for success, 1 for a refusal and 2 for a usage error, and every
message goes to stdout — the `accept` skill embeds the output through a `!`
line, and a refusal the researcher cannot read is the same as no refusal.
