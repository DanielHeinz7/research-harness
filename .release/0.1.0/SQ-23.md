---
ref: SQ-23
title: The guard now judges the file a write reaches, not the path it was given
bump: patch
plugins:
  - research-harness
---

A resolved path string is not a file. The `PreToolUse` guard decided whether a
`Write` or an `Edit` touched the research state by running `path.resolve` over
what the model typed and comparing the result to `research/canvas.md`, and
three ordinary names reached that file without matching it. On a
case-insensitive volume, `research/CANVAS.md` and `RESEARCH/canvas.md` were
allowed and overwrote the canvas, because `path.resolve` does not normalise
case. A symlinked file, a symlinked parent directory and a hard link were all
allowed too, because nothing in the resolution followed a link. In each case
the payload was the same forged canvas that the guard correctly refused at the
canonical path: an accepted statement deleted and a stated one reworded.

Resolution now goes through libc's `realpath`, which follows symlinks and hands
back the spelling that is actually on disk — that is what settles the case
variants, without the guard having to ask what kind of volume it is standing
on. A hard link is not a reference to a name but a second name for the same
file, so `realpath` cannot see it; device and inode can, and that is the second
comparison. A leaf that does not exist yet is canonicalised through its parent,
because creating a canvas is legitimate and has to stay judged, and a dangling
symlink through whatever it points at.

The third hole was the serious one, and it was not about paths at all.
`readIfExists` swallowed every error and returned `null`, so a canvas the
process could not read looked exactly like a canvas that was not there. The
guard read "no existing file", concluded that this was a file creation rather
than a modification, and permitted a write that deleted the researcher's
accepted statement. `chmod 000 research/canvas.md` was a way through the guard.
That inverts the rule the guard follows everywhere else: §5.3 says it denies
what it cannot judge, and it does exactly that for unterminated frontmatter and
for a body-wide code fence. An unreadable file is the same situation. `ENOENT`
— which is also what a dangling symlink reports — is now the only answer that
means absence; `EACCES`, `EPERM`, `EISDIR`, `ELOOP` and the rest propagate, and
the write is refused with a message naming the file it could not read.

What this costs. While a state file is unreadable, every write to it is
refused, including one the researcher would have wanted; restoring read access
is the way out, and that is the intended trade. The case-blind comparison only
decides paths that do not exist yet, since `realpath` has already settled the
ones that do, and it asks the filesystem whether a directory answers to a
flipped spelling of its own name rather than checking the platform. And
`research-harness status` and `review` will now surface the operating system's
error on an unreadable canvas instead of reporting, wrongly, that this is not a
paper project.
