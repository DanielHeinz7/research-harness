The guard has been rewritten four times since the one adversarial pass it ever
faced. SQ-21 attacked the version at SQ-16; the shell lexer, the canonical
commitment line, the seal chain, the state-directory perimeter and the
positional CLI inference that replaced it were all unprobed, in the one
component whose failure is silent.

`verification/SQ-29/` holds seven scripts that attack them, in the style of the
corpus already in `verification/probes/` and using the same `common.js`: one per
class, each driving the real `PreToolUse` hook, running or applying every
command the guard allowed, and re-reading the file. It also rebuilds the two
SQ-21 classes whose scripts were never vendored, from the rows in
`verification/recorded/`, and re-runs the three shipped scripts against both
`recorded/` and `SQ-32/probes-after.txt`.

The regression baseline is clean: the three shipped scripts produce the same
verdicts and effects as SQ-32 recorded, and every SQ-21 shell and path hole is
closed. The new classes found eight holes, which are filed separately. Nothing
in this change touches the guard.
