ref: SQ-57
title: The Bash guard denies a path assembled entirely from command substitutions
bump: patch
plugins:
  - research-harness
---

SQ-29 finding L15: a word built from two or more command substitutions with
no surviving literal fragment (`F=$(printf %s resear)$(printf %s ch/canvas.md);
rm $F`) left no literal text for `denotesState` to match, so the guard read it
as harmless and allowed the write.

Two changes close this. First, when a `$(...)`/backtick body is nothing but a
literal `echo` or `printf` of a constant, the guard now splices that known
output into the word as literal text instead of leaving an opaque mark, so a
path assembled from several such substitutions still reads as one literal and
flows through the existing assignment-tracking and path-matching machinery
unchanged. Second, as a fail-closed backstop, a word in a write position (a
command argument, a write-redirect target) that still carries an unresolved
substitution after that recovery is now an unknown target: denied unless the
command is read-only, exactly as an opaque word already is. A bare `$VAR`
reference is unaffected — only marks left by a substitution the guard could
not resolve are treated this way, so `echo x > "$LOG"` still passes. SQ-68, in
the same release, exempts a short list of verbs that never act on their
operands as files (`[`, `test`, `echo`, `printf`, `date`, `sleep`, `true`,
`false`, `mkdir`) from the argument half of this rule.

`verification/SQ-29/lex.txt` L15 now DENYs; every read-only substitution row
stays ALLOW. `plugins/research-harness/test/guard-promotion.test.js` gains the
substituted-path write and its read-only control.
