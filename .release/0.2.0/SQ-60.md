title: A `>&N` descriptor duplication names no path, so the guard reads none

SQ-29 finding "two rows that are neither" (`lex` L17/L19/L20, probes at
b4a7066). `readRedirect` consumed the `&` of a `>&`/`<&` form but kept the word
that followed as the redirection's target, so `2>&1` became a write into the
relative path `1`. After a `cd` whose target the guard cannot follow, that
refused a plain read — `cd "$HOME/…" && cat notes.txt 2>&1` (L19) — for
redirecting into a relative path, and `cd research && cat canvas.md 2>&1` (L20,
a read inside the state) for redirecting into the research state. Neither
command has a path in it: in bash every `[N]>&M` and `[N]<&M` whose word is
digits or `-` duplicates (or closes) a descriptor.

The lexer now flags that form and, when the word that follows is only digits or
`-`, reads it as the fd it is: the redirect writes nothing and the word is not a
command argument either. `>&word` and `&>word` with any other word keep being
the file redirections bash makes of them — `echo x >& research/canvas.md` (L21)
is still denied, and so is a target in the fd position the guard cannot read
(`2>&$fd` is not a digit, so it stays a file redirection and is refused where
that target cannot be judged).

`verification/SQ-29/lex-after-SQ-60.txt` re-runs the probe against this hook.
Against `lex-after-SQ-54.txt`: L19 and L20 flip to ALLOW (each executed under
/bin/bash, canvas unchanged), L21 and every other row keep their verdict and
effect. L17's verdict stays DENY and its reason changes from the fabricated
redirect to the real one — `` `node` is not a read-only command `` — because the
command carries a verb the guard does not read as read-only; L18 is the same
pipeline without the `2>&1` and has always read that way. The ticket expected
L17 to flip to ALLOW, which would mean allowing the `2>&1` pipeline while its
`2>&1`-less twin stays denied, so the verdict is left as it stands and only the
reason it was denied for is gone.

`test/guard-promotion.test.js` gains the pair: the descriptor forms that write
nothing (after a `cd` the guard can and cannot follow), the non-numeric targets
that stay writes, and the L17/L18 pipeline that is denied for its verb with and
without the `2>&1`.
