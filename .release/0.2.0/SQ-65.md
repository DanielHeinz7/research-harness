---
ref: SQ-65
title: A bare `research` in a tool payload is a name, not the state directory
bump: patch
plugins:
  - research-harness
---

With the guard installed, any tool payload that happened to carry the word
`research` — a board profile id, a topic, a title — was judged against the state
directory: the unknown-tool path asked whether a payload string *denotes* the
state and answered yes for a bare name, so `profile_get` with
`profile: "research"` was denied in every repository. The Bash path read a bare
word the same way, which refused `python3 x.py research` in a checkout that has
no `research/` at all. Both were reported from repositories that are not paper
projects, where the README promises the plugin stays silent.

Two conditions changed, in the place each path already judges from.

The unknown-tool path (`unknownToolVerdict`) now counts a payload string as the
state only when it names a state *file*, or spells a location — anything with a
path separator that lands under the state root. A bare name is a name. Every
spelling still reaches the verdict: `research/canvas.md`, `./research`, an
absolute path into the state and a path through a symlinked ancestor were denied
before and are denied after.

The Bash path (`wordTouchesState`, new `namesAbsentStateDir`) lets go only the
word that *is* the state directory and resolves to nothing: separator-less, no
pattern in it, and no such path on disk. So `rm -rf research` is still judged in
a paper project, and `python3 x.py research` is left alone in a repository
without the directory — the guard is inert where there is nothing to protect,
and fail-closed (§5.3) holds for every project that has the state. Everything a
pattern can reach is judged whether or not anything exists yet: a word one level
below the state (`cd research && rm -rf notes.md`), anything that spells a
location (`cat > research/canvas.md`, `git checkout HEAD -- research/`), and any
word with a pattern in it — `rm -rf resea[r]ch` expands onto the state directory
that is right there. (A JS array literal in a `node -e` body was matched as a
pattern for the same reason, the false deny `verification/SQ-29/lex.txt` L26,
L27 and L30 record; SQ-54, in the same release, fixes that by treating a `[…]`
as a pattern only when it compiles as a class.) `GLOB_META_RE` is now the one definition of what makes
a component a pattern, shared by `componentMatches` and the new name test.

`test/guard-promotion.test.js` gains three cases: a bare state name in a payload
is allowed while the path spellings still deny; without state the bare word is
allowed while a spelled path, `cat > research/canvas.md` and
`git checkout HEAD -- research/` still deny; and with the state directory there
the same words, plus `rm -rf resea[r]ch`, all deny. Reverting the file fails two
of the three (`AssertionError`), and probe-lex and probe-perimeter are
byte-identical to their SQ-29 recordings once the per-run temp names are
normalized.
