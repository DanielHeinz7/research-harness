---
ref: SQ-69
title: A flag that takes a value is not a script file, so a heredoc fed to a shell or interpreter stays its program
bump: patch
plugins:
  - research-harness
---

SQ-67's known gap, and it was wide. To decide whether a heredoc body is a
program or stdin data, the guard asked whether the receiving shell or interpreter
had a script file in front of the heredoc. It skipped the words that begin with
`-` and read the first bare word as that file. A flag that takes a value puts its
value exactly there, so the value was read as the script file and the body as the
script's stdin data:

    bash -o errexit <<'EOF'          errexit read as the script file
    rm research/canvas.md
    EOF

    bash --rcfile /dev/null <<'EOF'  /dev/null read as the script file
    rm research/canvas.md
    EOF

    python3 -W ignore <<'EOF'        ignore read as the script file
    import os; os.remove('research/canvas.md')
    EOF

    python3 -X utf8 <<'EOF'          utf8 read as the script file
    node -r fs <<'EOF'               fs read as the script file

Each of those ran. Only the bare forms — `bash <<EOF`, `node <<EOF` — were held.

The operand exit is gone. A shell or interpreter that receives a heredoc reads
its program from stdin unless an inline-program flag carries it, and the flag
spellings were widened to the ones the tools really accept: a shell's `-c` with
its letter not last in the bundle (`bash -ce PROG`, `bash -cs PROG` — no shell
takes a program attached to the letter, so nothing else changed there), an
interpreter's program attached to the flag letter (`python3 -c'PROG'`,
`perl -e'PROG'`), and a bundle of program letters with the program in the next
word (`node -pe PROG`, `perl -ne PROG`). Only letters known to be a program
letter or a print/loop flag it bundles with are read: `-Wignore` and `-Xdev` take
a value the guard cannot see, and reading them as a bundle would fail open, so an
unknown letter leaves the cluster unproven and the body is judged as the program
it may be.

Why the operand is dropped rather than kept for the cases it can prove: telling a
flag's value from a script file takes a per-interpreter table of value-taking
flags, and that table fails open for every flag it misses — which is this bug.
The cost is the other half of that trade, named in the code comment so it is not
rediscovered as a hole: `bash script.sh <<EOF` whose data body names a state write
is denied.

`plugins/research-harness/test/guard-promotion.test.js` gains the SQ-69 case: six
DENY rows (the five observed forms and the script-file cost), six ALLOW rows for
the inline-program spellings (`python3 -c'…'`, `node -pe`, `perl -ne`, `bash
-ce`), three DENY rows pinning the flags whose values stay unread (`-Wdev`,
`-Xdev`, `-m json.tool`), and the four unchanged controls — SQ-55's `cat`
receiver and the read-only bodies. Reverting the hook fails the case: the six
DENY rows come back as ALLOW.
