---
ref: SQ-76
title: A pattern below a state directory that holds no state is not the state
bump: patch
plugins:
  - research-harness
---

SQ-71 let the guard stand down in a project without research state, but for
patterns it did so only when the pattern stood for the state directory itself.
A deeper pattern still counted as touching. In a mail-mirror repository with no
`research/` at all, three read-only lines that count the mirror were denied on
2026-09-29:

    …; for k in …; do …; $(find $d -name '*.md' -path '*/20*/*' | wc -l) …; done   `for` is not a read-only command
    …; find mirror/history/inbox -name '*.md' -path '*/20*/*' | wc -l; du -sh …    `du` is not a read-only command
    find mirror/history/inbox -name '*.md' -path '*/20*/*' | wc -l && … && du -sh … `du` is not a read-only command

All three carry the quoted `find -path '*/20*/*'`. Resolved against the project
root it reads `<root>/*/20*/*`, its leading `*` matches `research`, and every
command on the line then had to be a named read-only form.

A glob expands only onto paths that exist; where nothing matches, the shell
passes the literal word on. So in a project whose state directory holds neither
the canvas nor the decision log, a pattern below that directory cannot land on
either file, and `namesAbsentStateDir` now lets it go. One exception: the
component that stands where the state files would, if it can match `canvas.md`
or `decisions.md`, is still judged. The guard reads the state once, on entry,
and a line that first creates it under a bare name that SQ-71 lets go
(`git checkout HEAD -- research && cp x.md research/canva?.md`) would have the
glob land on the new canvas. That line was denied before this change and still
is; a version that let every pattern go allowed it.

Nothing changes in a project that holds state. The spelled path
(`cat > research/canvas.md`), the harness state directory and the CLI's own
refusals are judged as before.

`plugins/research-harness/test/guard-promotion.test.js` gains one SQ-76 test:
the three kit-bridge lines and `rm -rf */20*/*` as ALLOW rows in a bare project;
the spelled path, the two create-then-glob lines and `rm -rf research/*` as DENY
rows there; a `find -path` line as an ALLOW row with an empty `research/`; and a
stateful control in which the same patterns still deny. No existing test was
changed.

SQ-75 (a word with an unresolved expansion that spells `research`, seen in the
vault) is a different path through `opaqueNamesState` and is not touched here.
