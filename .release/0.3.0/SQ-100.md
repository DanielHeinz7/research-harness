ref: SQ-100
title: Session view refuses an accept without the statement hash
bump: patch
plugins:
  - research-harness
---

`POST /api/accept` on the session server now returns 422 `invalid` when the request carries no `expectedHash`, as `/api/stated` already did. Before, such a request skipped the staleness check and could accept a statement the caller never saw. The view always sends the hash, so it behaves as before.
