---
ref: SQ-102
title: A variable holding another command no longer reads as the CLI
bump: patch
plugins:
  - research-harness
---

The promotion guard no longer mistakes a variable that holds another command for a CLI call when that command's argument is a directory named like the CLI, as in `G="git -C /src/research-harness"; $G add -A`. Bash splits the variable's value before it runs anything, so the program is `git`, and the guard now reads it the same way. A variable that starts the CLI, such as `node bin/research-harness.js` or `npx research-harness`, is still denied. A command that names `IFS` anywhere keeps the old reading, since a changed IFS decides where bash splits the value.
