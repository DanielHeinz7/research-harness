The first real import pilot (SQ-73) hit two small CLI defects, both fixed here.

`init --help` refused instead of helping: it printed `--project is required.`
and exited 2. `--help` and `-h` now print the usage and exit 0 on any
subcommand, and `research-harness` with no subcommand at all does the same. An
unknown subcommand still exits 2, because that is a mistake and not a question.

The second one cost a researcher real work. `init --outlet "open: ISR / MISQ /
ETP (...)"` wrote the value bare into the frontmatter, producing `outlet: open:
ISR / ...`. Pandoc reads that as a mapping inside a scalar and refuses the whole
canvas — "mapping values are not allowed in this context" — while this plugin's
own lenient frontmatter reader accepted it, so `status` and `review` looked
fine. The researcher could not repair it either: the frontmatter is theirs, and
the promotion guard rightly refuses the model's edit, so it had to be fixed by
hand.

`init` now writes the outlet and the project slug — the two frontmatter values
that are the researcher's own text — as double-quoted YAML scalars, and
`hooks/lib/canvas.js` reads the quotes and their escapes back off, so `status`
and `review` still show the value the researcher typed. `profile` and `mode`
stay bare, because `init` has already refused any value that is not one of the
plugin's own identifiers.
