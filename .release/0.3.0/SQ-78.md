title: Issue templates for reporting friction and bugs
bump: patch
plugins:
  - research-harness
---

A researcher who hits a slow step or a wrong result now has somewhere to put it.
The repository carries two GitHub issue templates: *friction* for something that
took longer than it should have or confused the reporter, and *bug* for a wrong
result or a crash. Both ask what the reporter tried to do, the command or skill
involved, what happened, how long it took, the version `/plugin` reports, and
whether `research/` state is involved; the bug template also asks for the exact
error text. Each says at the top that issues are public, so canvas and
decision-log text stay out of them. `config.yml` leaves blank issues enabled,
and the plugin README gained a short Feedback section after Use that points at
both templates.
