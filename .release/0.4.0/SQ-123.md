---
ref: SQ-123
title: Every accept needs the researcher's explanation, and records the check questions still open
bump: minor
plugins:
  - research-harness
---

`research-harness accept` now takes `--explained <text>`: one sentence, in the
researcher's own words, of what they accept and why it holds. Without it the
accept is refused with code `explanation-required` and nothing is written. The
explanation lands in the sealed DECISION as an `**Explained:**` line.

Check questions are DISCOVERY entries logged with ref `<n.m> check`. The ones
logged after the last DECISION on `n.m` count as open, and an accept records
them as `**Open at acceptance:** #a, #b`. They never block: accepting despite
them is allowed, and the output says which ones were open. The CLI and the
session server compute the list the same way, so both write the same bytes. The
server's `/api/accept` passes `explained` and `rejected` through; the view does
not send an explanation yet, so accepting from the view is refused until it
gets its explanation field.

`parseDecisions` now also returns `why`, `explained`, `rejected`,
`openAtAccept` and `supersedes` for every entry, next to the unchanged `body`.
