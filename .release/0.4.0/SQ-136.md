---
ref: SQ-136
title: `choose` refuses while the main canvas holds a `[stated]` statement, and lists every one
bump: patch
plugins:
  - research-harness
---

`choose` used to write the variant's body over everything below the main
canvas's frontmatter. An `[accepted]` statement stopped it; a `[stated]` one —
the researcher's own words, which the canvas skill says are never altered or
deleted — was dropped without a word.

It now refuses a `[stated]` statement too, with the same code (`already`) as the
`[accepted]` branch and before anything is written, so the CLI's exit status and
the session server's mapping treat both alike. The refusal names every `[stated]`
statement by its question and its text, cut to one line when the text runs long,
and says what to do: move each statement into the variant it belongs to, or
remove it, then choose again. Both markers are covered in one message when both
are present.

`[stated]` statements inside the chosen variant are unaffected: they are still
copied into the main canvas as before.
