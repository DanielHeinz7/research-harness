ref: SQ-144
title: The replacement-demo test spawns the CLI without an ambient project root
bump: patch
plugins:
  - research-harness
---

`test/replacement-demo.test.js` built the child environment as `{ ...process.env,
RESEARCH_HARNESS_STATE_DIR, CLAUDE_PLUGIN_ROOT }`, so a `CLAUDE_PROJECT_DIR` (or
`RESEARCH_HARNESS_DIR`) in the invoking shell reached the CLI. `hooks/lib/project.js`
prefers both over the working directory, so the CLI resolved the real project instead of
the test's temp project: `init` reported `research/canvas.md already exists; nothing
written.` and `recorded.js` read the temp canvas that no run had written. Two tests failed
in a Claude Code session and passed in a plain shell.

The test now drops both variables from the ambient environment before spawning, as
`test/demo.test.js` already does, and sets `RESEARCH_HARNESS_STATE_DIR` and
`CLAUDE_PLUGIN_ROOT` as before. No test assertion changed.
