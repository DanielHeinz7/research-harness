A whole word and a redirect target are now judged by where they land — symlinks followed and
case folded, as a link was already — so `./Research` and `Research/canvas.md` reach the state on a
volume that folds case, while a run of the state name inside a word's *text* counts only when it
lands on a state file (`canvas.md` or `decisions.md`). That keeps the earlier fix's coverage and
drops its false DENY: `sed -i '' 's/Foo\./Research/' notes.md` and `s/Foo\./Research Plan/` are
program text, not a path, and are allowed again on every filesystem.

A `sed -n` counts as a read only when its script holds no command that writes a file or runs one:
`w`, `W`, GNU's `e` command, the `w` and `e` flags of `s`, and a script read from a file with
`-f`/`--file` (unreadable, so not read-only). The guard parses sed's command syntax — addresses,
`s` with any delimiter, `y`, `{ }`, `;` and newlines — instead of matching the letter `w`, so
`sed -n '/Why/p'` and `s/w/W/g` stay reads. `less -o`, `-O` and `--log-file` are refused the way
`sort -o` is: probed under a pty they copy the input into the file when stdin is a pipe and stdout
a terminal, and which shape the shell hands `less` is not the guard's to know. Plain `less` over
the canvas stays a read. The perimeter probe covers the sed rows (M36-M39) and the benign corpus
carries the two restored `sed -i` shapes.
