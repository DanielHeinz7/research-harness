---
ref: SQ-146
title: Guard names an unreadable subcommand instead of calling it accept
bump: patch
plugins:
  - research-harness
---

A shell line that may run `research-harness` with a subcommand the guard cannot read — a word built at run time (`research-harness "$SUB"`) or a program text that only mentions the CLI's name, such as `node -p '…research-harness…'` — is still denied, and denied as strictly as `accept` is. Its denial text no longer claims the line runs `accept`: it names the unreadable subcommand, asks for it to be spelled out, and points at passing the text as data (printf it into a file and run the file) when the line only mentions the name. A literal `accept` subcommand, and every route the guard reads as `accept`, keeps the accept text.
