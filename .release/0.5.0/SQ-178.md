ref: SQ-178
title: Sessions are marked in the decision log
bump: minor
plugins:
  - research-harness
---

`research-harness session start "<occasion>"` writes a sealed `SESSION` entry
into the decision log, e.g. `## [#52] 2026-10-08 · SESSION · Supervision with
B. Supervisor · seal …`, carrying the same `By` as every other entry. A session
runs until the next marker or the end of the log. `log` still writes only
DISCOVERY and CONSTRAINT: a marker comes from its own command, never from a
finding, and neither SESSION nor MERGE counts as a finding for the
hypotheses-before-data check. Two markers in a row are allowed — the first
session is then empty — and `research-harness doctor` notes them without
failing on them.
