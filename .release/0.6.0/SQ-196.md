ref: SQ-196
title: merge-log refuses before writing when the merged log cannot verify
bump: patch
plugins:
  - research-harness
---

`research-harness merge-log` now refuses before it touches
`research/decisions.md` when the merged log would not verify. The case: our
side carries no seal and theirs holds no entries, so the merge would have kept
ours unchanged, written it, and only then failed its own verify. That was the
one refusal that left the working file modified behind its "do not commit".
The refusal now comes from `mergeLogs` before any text is returned, so the
working file stays byte-identical like it does for every other refusal. The
CLI's post-write verify stays as the backstop.
