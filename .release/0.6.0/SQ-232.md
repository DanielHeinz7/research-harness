---
ref: SQ-232
title: Guard judges heredoc data that names the research state
bump: patch
plugins:
  - research-harness
---

A heredoc body that is stdin data, not a program, is now judged on the paths it spells, the way a `printf` or `echo` argument already was. `xargs rm <<'EOF'` with `research/canvas.md` in its body removed the canvas, and so did `cat <<'EOF' | xargs rm` and `while read f; do rm "$f"; done <<'EOF'`; each is now denied, with a quoted or an unquoted delimiter. Lines that only read still pass, such as `cat <<'EOF'` or `git commit -F - <<'EOF'` with a message that names the canvas. Any other command fed a heredoc that names a bare `research/...` path is denied, as its `printf ... |` form already was; that includes an inline program such as `python3 -c '...' <<'EOF'`. A path outside the state, such as `vault/research/x.md`, passes. A heredoc that a shell or interpreter reads as its program is judged as before.
