---
ref: SQ-234
title: Guard cuts data reaching read loops and xargs -d into items
bump: patch
plugins:
  - research-harness
---

A `read` anywhere on a line now counts the way `xargs` and `parallel` do, so the data it reads is judged item by item. `while read f; do rm -r "$f"; done` over a heredoc listing `notes` and `research`, or the same loop fed by `printf "notes research\n"`, removed the state directory; both are now denied, as the one-line body already was. The delimiter that `xargs -d` or `--delimiter`, `read -d` or an `IFS` assignment sets also ends an item, so `xargs -d , rm -r` over `notes,research` is denied too. On such a line what `printf` and `echo` print counts as data, with `\n` and the other escapes resolved. A delimiter the guard cannot read leaves the items unknown, which is refused where research state exists. Data rewritten on its way to the reader (`tr`, `sed`, `awk`, `cut`) is not followed. A quoted `echo` or `printf` argument that names `research` on a line that also runs `read` or `xargs` and a command that writes is now refused, as its unquoted form already was.
