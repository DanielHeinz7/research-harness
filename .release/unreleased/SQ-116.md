title: The CLI runs in the researcher's own terminal: `bin/research-harness` and `install-cli`
bump: patch
plugins:
  - research-harness

`bin/research-harness` is a new executable door onto the existing program: same
argv, same stdout and stderr, same exit code. The bare command now works
wherever the plugin's `bin/` is on PATH, which inside a Claude Code session is
the Bash tool.

`research-harness install-cli [--dir <path>]` writes a shim named
`research-harness` into `~/.local/bin` (created if missing) that resolves the
plugin's install path from `installed_plugins.json` at every run, so a plugin
update leaves it working. It prints the shim's path and whether that directory
is on PATH, with the one `zsh` line to add if it is not. It edits no rc file and
refuses to overwrite a file that is not its own shim; when the plugin is not
installed, the shim says so in one line and exits 1.

`doctor` gains a check, "terminal command": it passes when a shim is at
`~/.local/bin/research-harness` or on PATH, and otherwise prints the line that
points the researcher at `install-cli`. The promotion guard lets the model run
`install-cli` in a project with state — it writes outside the research state —
while `accept` and `serve` keep their rule unchanged. The README install steps
now cover the private repository and the one-time `install-cli` run.
