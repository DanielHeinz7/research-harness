---
ref: SQ-122
title: `init` in a clone no longer creates a key and turns a sealed log into a false BROKEN
bump: patch
plugins:
  - research-harness
---

`init` on a project whose `research/decisions.md` already carries seals creates no
key any more. Those seals were written under the key of the machine the project
started on, and a fresh key here made every one of them fail to recompute, so
`review` reported an intact log as BROKEN at its first sealed entry. The command
now prints one line naming the log as sealed on another machine and the path the
key belongs at, changes nothing, and exits 0. A log that carries no seal yet —
empty, or written before the seal existed — still gets a key there, as before. The
README's clone section now says what to do instead: copy `seal.key` from the
sealing machine if this checkout has to write sealed entries.
