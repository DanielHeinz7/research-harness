title: A received record verifies off the authors' machine with `--key`, against a printed anchor

`review` and `status` take `--key <file>`: the record's sealing key as it was
released to a reviewer, used for verification instead of the key this machine
would read. A key file that cannot be read, or that does not hold 32 bytes, is
refused in one line before anything is judged — a short key would report a sound
log as BROKEN.

`review` now prints the anchor of the record it has, as its own section:

    ## Anchor
    Anchor: last seal 9c53940787bd2e3a, maxSeq 4, decisions.md sha256 a388c0f0…

The reviewer compares that line with the one the authors published. An anchor
printed now matches a rewritten log too, so what detects a rewrite is the copy
published earlier — a tag, the submission, a mail — and the README's new
"Verifying a record you received" section says so, together with the honest
limit that a seal proves a machine that held the key, not a person.
