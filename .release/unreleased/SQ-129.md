title: The session view compares framings, chooses one, and accepts with an explanation

Since the server began to require an explanation, the session view could not
accept at all: it sent none. **Accept…** on a statement now opens a dialog that
shows the statement as it stands (never editable there), asks "In your own
words, why does this hold?" and will not send an empty answer. The check
questions still open on that statement's question are listed above the buttons,
each with the `#seq` of the log entry that asked it; with some open the button
reads **Accept anyway**, without, **Accept**. What the server refuses (a label
line in the text, a stale statement) is shown inside the dialog.

A **Framings** tab appears while the project holds variants. It is the poster's
own cards, one column per framing headed by its name and lens, one row per
field. A field whose statements differ between framings carries a "Differs"
tag and the poster's accent edge; a field that reads the same in every framing
is faded. A card leads with one sentence; "All n statements" opens the rest,
so a difference below the lead is never hidden. **Choose this framing** opens a
dialog with a required reason and "what you are setting aside" prefilled from
the other framings and their lenses, as the server's default would write it,
and editable. The button is disabled, with a one-line reason above the columns,
while the main canvas holds an accepted or a stated statement; if the server
still refuses, its message (which lists the stated statements) appears in the
dialog. After a choice the view shows the main canvas.

History numbers its entries (`#3`) and shows the new lines quietly, in the
existing style: Explained, Rejected, and Open at acceptance as `#seq` links that
scroll to the entry they name. A framing choice reads "Framing chosen" with the
variant's name. The entry parser now treats an entry's first line as its text,
as the library does, so a text that looks like a label is never drawn as one.

In fixture mode `?view=compare|log|element-1|…` and `?dialog=choose:<name>` or
`?dialog=accept:<question id>` open a view or a dialog on load, for screenshots;
the dialogs' confirm button writes nothing there. `test/fixtures/make-variants-fixtures.js`
regenerates the two new fixtures from a scratch project through the CLI.
