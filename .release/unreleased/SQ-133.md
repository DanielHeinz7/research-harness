---
ref: SQ-133
title: A log body can no longer forge the parsed fields (Explained, Open at acceptance, Supersedes)
bump: patch
plugins:
  - research-harness
---

A free-text value written into the decision log may no longer contain a line that starts like one
of the format's field labels (`**Why:**`, `**Explained:**`, `**Rejected:**`, `**Open at
acceptance:**`, `**Supersedes:**`). `parseDecisions` reads such a line back as that field from
anywhere below the entry's text, so `log DISCOVERY … --body` or `--why` could carry an explanation,
a supersede or an open-check line that no approval path ever wrote. Every write — `log`, `accept`
and `choose` — refuses it with one line naming the label.

The entry's own first line is its text — the statement of an acceptance, the question of a check —
and is never read as a field: a statement whose text is `**Supersedes:** #2` stays text, and the
entry records no supersede from it. The refusal and the parser read the same label grammar, so the
two cannot drift apart. Nothing about the seal or the stored bytes changes: a log sealed before
this change still verifies and parses to the same fields, and a fixture sealed at the previous
revision now guards that.
