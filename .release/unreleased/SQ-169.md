---
title: A code fence closes by CommonMark's rule, not at any three backticks
bump: patch
plugins:
  - research-harness
---

A line of three backticks or tildes used to close any open fence, so a shorter
run inside a longer fence ended the block early. A committed statement after it
was treated as visible and dropped from "Committed but not visible", although a
reader of the rendered canvas sees it as code. A fence now closes only on a run
of the fence's own character, at least as long as the one that opened it, with
nothing but whitespace after it. A shorter run, the other fence character, or a
line carrying an info string stays inside the block, and the commitments under
it are reported again.
