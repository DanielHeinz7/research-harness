title: The guard lets the model read the agenda and a session protocol, and refuses every exported key file
bump: minor
plugins:
  - research-harness
---

The model may now run `research-harness agenda` and `research-harness session
protocol [<n>]`, which only print. Either one with `--out` writes a file, so the
guard refuses it, and it refuses any flag, unknown word or extra word on these
two lines, because a flag the CLI does not know takes the next word as its value
and moves which word the CLI reads as the action. `name`, `session start`,
`merge-log`, `key` and `join` stay the person's. The refusal now lists the read
subcommands: status, review, init, doctor, install-cli, title, agenda, session
protocol and log.

A file whose name ends in `.seal.key` is an exported sealing key, and no tool may
read, copy or write one, wherever it lies: by its name in any case, through a
glob that expands onto one, through a symlink, or as a redirect target.

Three ways around the subcommand check are closed. A flag in front of the
subcommand (`research-harness --x status accept 1.1`) made the CLI run `accept`
while the guard read `status`; the guard now finds the subcommand the way the
CLI's argument parser does. Words that `xargs` adds from stdin (`echo accept 1.1
| xargs research-harness`) count as unknown. `$'…'` and `$"…"` quoting is read
the way bash reads it, so `$'--out'` is `--out`.
