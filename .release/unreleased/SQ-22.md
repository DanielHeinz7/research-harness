---
ref: SQ-22
title: The shell guard now reads the command instead of matching strings
bump: patch
plugins:
  - research-harness
---

The `PreToolUse` guard used to decide a `Bash` command by looking for the
substring `canvas.md` in it and then asking whether it began with a read-only
verb. Both tests were trivially evaded: of 38 probe commands driven through the
real hook, 17 were allowed and then proven to change the file — a `rm` chained
behind a `cat`, a glob or a split quote in the redirection target, a path
assembled in a variable or a command substitution, `awk` redirecting from
inside its own program, `rm -rf research`, a link out of the directory, and
`research-harness accept` spelled three ways the pattern did not recognise.

Those are not separate cases to enumerate. They are one intent written
differently, and that is exactly what a string test over an unparsed command
line cannot see. So the guard now lexes the command — quoting, chaining,
redirections, `$(...)`, `${}` and `$NAME`, assignments, heredocs, `cd` — and
asks one question of every word it finds: can this denote the research state
directory? Where one can, the command has to consist entirely of named
read-only forms, and everything else is refused. Inside the scope the lexer can
see, the answer is no unless the command is recognised; outside it, the guard
stays out of the way as before.

What this costs, deliberately. `awk` is no longer a read-only command over
these files: `print > f` inside its program writes one, and that program is a
language this guard cannot read. A redirection whose target is assembled at run
time is refused when the command touches the state, though a plain `> "$LOG"`
with no literal path in it is not. After a `cd` the guard cannot follow, every
later command that is not a read is refused, because nothing can be shown to
stay outside. `git add` and `git commit` are now read-only here, since neither
rewrites a tracked file and refusing them would have meant refusing a commit
for naming `research/canvas.md` in its message.

One limit is worth stating rather than hiding. A word that is only an ancestor
of the state directory — `.`, `..` — does not engage the guard, so `rm -rf .`
is not caught. Catching it would cost `git add .`, which is an ordinary thing
to run in a research project, and this is a guard over who may commit a
statement, not a sandbox against a command that destroys the whole project.
`rm -rf research`, which names the directory, is caught.
