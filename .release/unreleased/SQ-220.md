title: Refuse a lost glossary update in one line and cover no duplicated id
bump: patch
plugins:
  - research-harness
---

Review no longer reads a decision as cover for an entry whose id two headings
share: such an id is not a link target, so neither block counts as accepted, and
a still-standing accepted payload is no longer reported stale just because a
second heading shares its id. `glossary accept` prints a glossary changed during
publication as the same one-line refusal every other refusal is, exit 1 with the
concurrent edit preserved, instead of a Node stack trace. The glossary-accept
skill says the researcher resets a marker-only entry to `[proposed]` by hand and
that the guard refuses that edit to the model.
