ref: SQ-233
title: Guard judges heredoc data fed to xargs or expanded by bash
bump: patch
plugins:
  - research-harness
---

On a line that runs `xargs` or `parallel`, a heredoc body is now judged item by item, the way an argument word is. `xargs rm -r <<'EOF'` with `research` on a line of its own, or beside another name, removed the state directory; it is now denied, as `printf '%s\n' notes research | xargs rm -r` already was. Items are split the way xargs splits them, quotes and backslashes removed, and each whole line counts too. A heredoc whose delimiter is not quoted is also judged as the text bash expands it to, so `$PWD/research/canvas.md`, `${d}earch/canvas.md` and a variable the line assigned count like the same text as an argument. Under any other command the body keeps the path rule from SQ-232, so prose that mentions research, such as a `cockpit rueckmeldung` message, still passes. A token that joins a variable to a path through `research` is refused there, as its `printf ... |` form already was.
