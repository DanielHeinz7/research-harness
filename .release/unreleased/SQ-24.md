ref: SQ-24
title: The guard now sees every tool, not the four it was told to watch
bump: patch
plugins:
  - research-harness
---

A guard that knows four tool names protects a file from four tools. The
`PreToolUse` matcher in `hooks.json` named `Edit|Write|NotebookEdit|Bash`, so
nothing else ever reached the guard, and `main()` switched on those same four
names and returned ALLOW for anything it did not recognise — the same list
written twice, failing open in both places. `MultiEdit`, an MCP filesystem
server's `write_file`, and a tool called `create_file`, each carrying a canvas
with the researcher's `[accepted]` statement deleted, were permitted in silence.

Adding those three names would have protected the file from seven tools, and
left the next one through. So the default is inverted rather than extended. The
matcher is gone: every tool reaches the guard, and which of them it can judge is
decided in the guard alone, instead of half in a regex in the configuration and
half in a switch in the code. A tool it recognises is still judged by the write
it would perform, exactly as before. Every other tool is judged by where its
payload points — every string in the payload, whatever key it sits under and
however deep, because the keys belong to the tool's schema and an allowlist of
keys is the same defect one level down. A payload that points at the research
state is refused: an unknown tool reaching the canvas is precisely the "cannot
judge this write" case §5.3 already fails closed on. The refusal names the file
by where the write would land, so a symlink, a hard link and a case variant all
report `canvas.md`.

What this costs. A tool this guard has not heard of cannot touch `research/` at
all — not `canvas.md` and `decisions.md`, not the directory, not anything in it,
and not to read it either, since nothing about an unknown tool says which it
would do. Read, Grep, Glob and NotebookRead stay open, because reading the
canvas is how the harness works. A payload field whose whole value resolves into
the state directory is enough to refuse the call; prose that merely mentions
`research/canvas.md` is not, because it resolves to a file of that unlikely name
beside the project and is nobody's business.

One thing this does not yet prove. The tools above were driven through the real
hook with forged payloads, which shows what the guard decides. It does not show
that the client hands an `mcp__*` call to a `PreToolUse` hook in a live session
— the documentation says it does, and confirming it needs a running session
rather than a spawned one. That check belongs with the live installation test.
