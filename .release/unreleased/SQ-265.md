---
ref: SQ-265
title: A research file with Windows line endings is refused, not read as empty
bump: patch
plugins:
  - research-harness
---

Git for Windows checks text files out with CRLF line endings by default, and
research-harness used to read such a file as empty: a canvas with no
statements, a decision log with no entries that still passed its own seal
check. A CR directly before an LF is now a refusal everywhere. The canvas and
glossary parsers report it as a structural problem naming the first such line,
and `verifyChain` answers `broken` with the reason `line-endings`, so nothing
is appended to a log whose first seal would anchor over CR bytes. The refusal
names the file and points at the README. The harness does not repair the file:
no canvas, glossary or log is rewritten.
