ref: SQ-266
title: Every reader gives the same refusal for Windows line endings
bump: patch
plugins:
  - research-harness
---

A project whose canvas or decision log has Windows line endings (CRLF) now gets one refusal from `status`, `review`, `accept`, `choose`, `log` and the app's sidebar. That refusal names the file and the first CRLF line, where these readers used to say "not a paper project" or show an empty sidebar. The guard also refuses an agent's edit of a CRLF canvas or glossary, including an edit that would rewrite the whole file with LF line endings.
