---
ref: SQ-28
title: An unreadable canvas is reported on one line, not as a stack trace
bump: patch
plugins:
  - research-harness
---

SQ-23 made `readIfExists` let every error but `ENOENT` through, so that the
guard can tell a canvas that is absent from one it cannot read. The CLI had no
answer for the second case: `research-harness status` and `review` printed a
Node stack trace on a canvas with mode 000, where before SQ-23 they had said,
wrongly, that this was not a paper project.

The entry point now catches a filesystem error from the state files and
prints one line with the file and the error code, on stdout like every other
message so a skill can still embed the output, and exits 1. `ENOENT` keeps its
"not a paper project" message. `EISDIR` is raised by `read`, not `open`, and
carries no path, so that line names the state directory instead. An error that
is not from the filesystem is a bug and keeps its trace. `readIfExists` and the
guard are unchanged; their behaviour is the fix, not the bug.
