title: Desktop app: a refusal in the session view never names a terminal command, and the name lookup runs the git the app brought
bump: patch
plugins:
  - research-harness
---

In the desktop app, the session view's own write routes (accept, choose, mark as said, comment) answer in the app's words where the ledger's sentence named a command: "Join this project first" with where the key file comes from when this computer has no key for the project, and the request for a name when the decision log has none for this machine. A broken chain or a key file that cannot be read still reads as what it is, and nothing is written in any of these cases. The command line and a plain `research-harness serve` keep their sentences byte for byte. The name an entry carries now comes from the git the app brought with it (`RESEARCH_HARNESS_GIT`) when the app gave the server one: an app started from Finder has `/usr/bin` in PATH, where git on a Mac without the developer tools is a stub that opens the system installer. Without that variable the git from PATH answers, as before. Seal chain, log format and guard are unchanged.
