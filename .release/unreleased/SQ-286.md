ref: SQ-286
title: The decision log names its sealing key, so join refuses a wrong key file on an empty log
bump: patch
plugins:
  - research-harness
---

`init` now writes a `Seal key: <16 hex>` line under the title of a new decision log. The value is a keyed hash of the project's key over a fixed label and gives nothing away about the key. A key that does not match the line makes the chain read as broken (`key`), so `join`, every write, `merge-log`, `review` and `doctor` refuse a wrong key even while the log has no sealed entry, and each says in a sentence that the key is not the project's. Before, an empty log, or one whose entries all predate the seal, accepted any key file at `join`. `init` also refuses to create a key on a computer that has none when the log carries the line, and points to `join` instead. Old projects without the line keep working: `join` on an empty or unsealed log says the key could not be checked and goes on, and `key export` (Invite co-author… in the app) adds the line to such a log, because the exporting computer holds the right key; commit and push it before handing over the key file. A sealed log without the line keeps its bytes, since its seals already tell keys apart. Variant logs get no line.
