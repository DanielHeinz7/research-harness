title: Desktop app: Share survives an interruption, sends only the research files, and names no paths
bump: patch
plugins:
  - research-harness
---

Hardening of the app's sharing steps from the review of SQ-279. A share that
stopped between the link and the upload is no longer a dead end: the sidebar
keeps offering Share with co-authors… and pasting the same link again finishes
the upload, while another link is refused with the one the project is connected
to. "Shared copy" now means an origin *and* an upstream branch, so a stored
link alone no longer hides Share or hands a co-author a link to an empty
repository. Send, Update and Share commit the research files only, so a project
that was opened inside another repository no longer uploads that repository's
other work, and the Share dialog says that the project's history as it is goes
up. A project folder inside another repository reads its own `.git` and no
longer reports the parent's origin. Names with control characters, or with
nothing but `<` and `>` in them, are refused in the dialog instead of failing
every later Send and Share. Links are shown with everything up to the last `@`
stripped whatever the scheme, and a link that carries a password is refused
rather than stored in `.git/config`. A key file that cannot be read reads as
"this computer's key for the project cannot be read" without the path inside
the app's state folder, and the sidebar offers Join as it does without a key.
A network command gives up after 120 s without output — ten minutes while the
app's login dialog waits for the person — and says so, instead of hanging
forever; no message repeats node's own command line with its paths. Seal chain,
log format and guard are unchanged.
