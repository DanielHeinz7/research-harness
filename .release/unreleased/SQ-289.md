title: New projects keep LF at the source, and the README says how to repair an older clone
bump: patch
plugins:
  - research-harness

`init` now writes `research/.gitattributes` with `* text eol=lf`, so every research file keeps LF in every checkout, also on Windows where Git for Windows checks text files out with CRLF by default. An existing `research/.gitattributes`, and a repository's own root `.gitattributes`, are left alone. The desktop app clones with `core.autocrlf=false` written into the new clone's own config, so a project created before this change still arrives with LF. The README has a "Windows line endings" section with the two commands that repair a copy you cloned yourself.
