Five follow-ups from the review of SQ-293. A write to a variant log now checks the key against the main log's `Seal key:` line and is refused in the same words the main log uses; before, a variant write sealed with any key. `join` replaces a stored key the log's line contradicts when the key file you give matches that line, and says in one sentence which key it went with — a key file that does not match still replaces nothing, and on an old log without the line the refusal stands. A key that is not the project's no longer reads as a changed entry: `status`, `session protocol` and the dashboard name the key as the cause and point at `join`, with no link to an entry number that was never touched. On a clone whose log already names the project's key, `log` and `doctor` send the researcher to `join` with the key file instead of to `init`, also while no entry is sealed yet. `init --project` refuses a name with a line break or a carriage return before it writes anything, with a sentence naming the characters; before, such a name split the log's title line, and a name carrying `Seal key: …` made the command fail with a stack trace.
