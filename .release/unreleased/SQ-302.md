ref: SQ-302
title: The agent's query options are pinned, the guard's start is checked, and a server error is told apart from a refused connection
bump: patch
plugins:
  - research-harness
---

The desktop agent now starts the bundled plugin from one fixed set of query options: the ten tools, `acceptEdits`, a sandbox that denies every secret variable, and no replaced system prompt, no `settings`, and an empty `settingSources`. The connection test gets its own one-turn options with no tools and no plugin. A guard check decides whether the guard has started from the SessionStart hook result and the commands `initializationResult()` lists, before the first message goes out, and reads the version it shows from the bundled manifest. A genuine server error now reads as its own line, "… reported a server error. Try again in a few minutes.", instead of being reported as an unreachable host; a refused connection still reads as unreachable.
