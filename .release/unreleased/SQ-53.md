SQ-29 finding F4 (M9/M9b): the Bash closure around the harness state
directory (`wordTouchesHarness`) only compared path spellings against the
state root, never what a candidate word actually pointed at. The file-tool
path already resolves symlinks with `canonical()` before comparing; the
Bash-side closure did not, so a symlink anywhere above the state directory —
whether it already existed on disk or was made by an earlier statement in the
very same not-yet-executed command (`ln -sfn . h && cat h/.../seal.key`) —
read the sealing key straight through it.

The Bash closure now resolves every candidate word the same way: it tracks
`ln -s TARGET LINKNAME` across the statements of one command the way it
already tracks `cd`, then resolves the result through `canonical()` before
comparing it against the state root. The plain spelling comparison stays as
the first check, for paths that do not exist yet; the resolved-path check is
an additional fallback, not a replacement. M1–M8 and M10–M18 are unchanged.

`verification/SQ-29/perimeter-after-SQ-53.txt` re-runs the perimeter probe:
M9 and M9b now DENY.
