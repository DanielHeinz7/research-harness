SQ-29 finding F5 (lex L26/L27/L30/L33, perimeter M10) — two faces of one
comparison inside `denotesState`/`componentMatches`.

**The false deny.** Any word with a `[` in it was a glob, and a pattern the
regex engine refused was answered *matches*: the word named the research state
because it could not be compiled. So `node -e 'const r=["SQ-28","SQ-30"];…'`
was denied for its verb in a project where the program text names nothing that
exists — the live command that opened F5, and the three verdict-only seed rows
built from it.

**The false allow.** The candidate was the pattern and the state's own path
component the literal, so a directory whose name holds brackets never matched
itself. In a paper project called `paper[2024]`, `rm research/canvas.md` was
allowed and the canvas was gone (L33); with the state root named `.state[2024]`,
`cat <stateRoot>/…/seal.key` printed the sealing key (M10). The guard was blind
to the state it exists to protect, in exactly the directories whose names are
least likely to appear in a test.

`isPattern` is now the single answer to *is this word a glob*: a `*`, a `?`, or
a `[…]` body that compiles as a class. Anything else is the literal it spells
(`GLOB_META_RE` stays SQ-65's character pre-filter, called only from there — no
second definition of a pattern). `componentMatches` compares equality first, so
a component that spells the state's own name *is* that name. A word that is
genuinely a pattern and whose class the engine refuses is neither a match nor a
miss: `componentMatches` answers `null`, `denotesState` and `wordTouchesState`
carry that up, and `bashVerdict` refuses it — with its own reason — wherever
there is a write to refuse, a redirect target included. Under a read-only verb
nothing is written, so the same word stays the name it spells.

`verification/SQ-29/lex-after-SQ-54.txt` and `perimeter-after-SQ-54.txt` re-run
the two probes against this hook. Against `HEAD`: lex L26, L27 and L30 ALLOW,
L33 DENY; perimeter M10 DENY; the other 30 lex rows and 18 perimeter rows are
unchanged in both the verdict and the deny-reason column. `resea[r]ch` — a class
that *does* compile — still expands onto the state directory and is still denied
(SQ-65). The `lex.txt` and `perimeter.txt` recordings stay as they are: they are
the finding at `cbed3d4`, and the `-after-` files are the gate. SQ-65's note read
the array-literal false deny as that rule working as intended; L26/L27/L30 are
literals now, and the deny those rows recorded is the bug this commit removes.

`test/guard-promotion.test.js` gains three cases: a bracketed literal is a
literal (and a read-only verb over the same word is unaffected); a project whose
own name holds brackets still recognises its state (write denied, `cat` and
`sed -n` allowed); a pattern the guard cannot compute is denied where there is a
write and left as a name where there is not.
