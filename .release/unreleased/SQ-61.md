ref: SQ-61
title: An opaque command word no longer hides the invocation behind it, and an unknown variable is a write target
bump: patch
plugins:
  - research-harness
---

SQ-29 finding, cli B10 (`verification/SQ-29/cli-after.txt`).

The positional inference in `harnessInvocation` read the command word first and
gave up when that word was opaque. `R=$(cat x); $R bin/research-harness.js accept
1.2` therefore reached the CLI unseen: the runner stood in a variable whose value
only the shell could resolve, so word 0 was opaque and the words after it — the
CLI name and `accept` — were never read. The same hole sat in argument position,
which SQ-57 delivered: an assignment from a substitution the guard cannot resolve
left the variable untracked, so the `$x` that named the file stayed a mark with a
name and was never treated as a target. `x=$(cat p.txt); rm "$x"` was allowed.

Two readings close both positions. An opaque command word is now read the way an
unknown wrapper is: the slots after it are walked, so a CLI name or `accept` in
the position the runner or direct branch would read is the invocation it would
have been. `$CMD --version` and `$R echo hi` name neither and stay allowed. And
an assignment whose value carries an unresolved substitution now records that
unknown as the variable's value instead of dropping the variable, so `$x` is an
unknown target where it stands: denied under a verb that writes its operand
(`rm "$x"`, `mv a "$x"`), allowed under a read-only one (`ls "$x"`, `cat "$x"`),
the same reading SQ-68 gave a substitution written out in the argument itself.

The cost is the same one, stated plainly: the value of `$(mktemp)` or `$(pwd)` is
unknown to the guard, so `tmp=$(mktemp); rm "$tmp"` is now denied inside a
research project. The guard judges an unknown operand like a literal one; name
the path literally, or read it with Read.

`verification/SQ-29/cli-after-SQ-61.txt` re-runs `probe-cli.js` with two rows
added beside B10 for the two opaque forms (an unresolvable substitution and a
variable never assigned); B10 itself is denied since SQ-57 read `$(echo node)`
into the literal `node`. Every other row is unchanged and the SQ-32 controls
stay allowed. `test/guard-promotion.test.js` gains the word-0 and
argument-position cases beside the wrapper tests.
