---
ref: SQ-67
title: A heredoc fed to a shell or interpreter is program text, and the guard lexes it as the script it is
bump: patch
plugins:
  - research-harness
---

SQ-29 finding: since SQ-55 the guard reads a heredoc body as stdin data — it
scans an unquoted body's substitutions, and the rest reaches the receiving
command as text on its stdin. That is right for a data receiver (`cat <<EOF`)
and wrong for a receiver that reads its program from standard input: `bash <<EOF
… EOF` runs the body, and so do `sh`, `zsh`, `dash`, `ksh`, `ash`, `bash -s` and
`bash -`, `node`, `python3`, `perl` and `ruby`. Quoting the delimiter does not
help: it stops the expansion, but the body still reaches the shell as its
program, so `bash <<'EOF'` runs `rm research/canvas.md` literally.

The guard now recognises that receiver — the command a chain of wrappers
launches, with neither an inline program flag (`sh -c PROG`, `node -e PROG`) nor
a script file operand, and with `-` or `-s` forcing standard input back on — and
lexes the body as the script it is, recursively, at the depth the substitution
scan already nests an unquoted body's `$(...)`. That is the choice SQ-52 and
SQ-55 already fixed for `sh -c`: the body is program text, and every command in
it is judged in its own right rather than left as opaque data whose names the
verdict only guesses at. The receiving command is marked as a launcher, so
`bash <<EOF` with a body that only reads the state still reads; its own
redirections are judged as before (`bash > research/canvas.md <<EOF` is denied on
the redirect). A body the scan cannot finish is opaque and carries `unreadBody`,
the rule an opaque word already follows.

The here-string (`bash <<< 'rm research/canvas.md'`) and the pipe
(`echo … | bash`) need no change: both hand the state name to the receiving
shell as an operand word, which SQ-52's opaque-word rule already held.

Known gap, closed by a follow-up: a flag that takes a value (`bash -o errexit`,
`python3 -W ignore`, `node -r fs`) is still read as a script file operand, so the
body counts as data.

`plugins/research-harness/test/guard-promotion.test.js` gains the SQ-67 case:
fifteen DENY rows (seven shell forms, four interpreters, a wrapper, the shell's
own redirect, a body naming `accept`, a body substitution), the here-string and
pipe rows that were already held, and the read controls — a body that only reads
the state, a benign program, and SQ-55's `cat <<EOF` data rows with the same
write text. The lex class is unchanged: `node verification/SQ-29/probe-lex.js`
reproduces all 34 rows of `verification/SQ-29/lex-after-SQ-54.txt` exactly, and
`node verification/SQ-29/probe-baseline.js` reports NO REGRESSION on all three
recorded classes.
