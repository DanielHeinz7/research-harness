---
ref: SQ-75
title: Brace expansion and loop values are judged; without state, only a word that can land on a state file counts
bump: patch
plugins:
  - research-harness
---

Three findings, replayed on main 37c7fce.

**Brace expansion was not modeled.** In a project with research state,
`rm -rf {research,tmp}` was allowed. Bash expands braces before anything else,
so that line removes the state directory. `cp a.md {research,x}/canvas.md` and
`cp a.md rese{arch,x}/canvas.md` were allowed for the same reason: the lexer
split words on `{ , }` and never saw `research/canvas.md`. The lexer now keeps a
second spelling of every word with an unquoted brace, in which only the
unquoted `{`, `,` and `}` are marked. `bashVerdict` expands it the way bash
does (alternatives, prefix and suffix, nesting, `{1..3}` and `{a..e}`
sequences) and judges every word it expands to. A quoted or escaped brace is
not expanded, and `${var}` is not brace syntax. Past 256 words the expansion is
not computed. That word is then one the guard cannot judge: with state it is
refused where there is a write, like a pattern it cannot compute; without state
it is read on the names it spells, like an opaque word. A `$(echo …)` whose
words carry a brace is no longer spliced in as a literal.

**A loop variable made a word unknown.** `for n in a b; do ls -d research/$n;
done` left `$n` unresolved, and the unknown word naming `research` denied the
whole line with "`for` is not a read-only command". A `for NAME in W…` over
literal words (after brace expansion) now makes every later word that uses
`$NAME` one word per value. A loop over anything the guard cannot read leaves
the variable unknown, as before, and an assignment to the name ends the loop
values.

**Without state, a word below the state directory counted as the state.** In
a vault whose `research/` is a notes folder, `git mv research/a.md
research/b.md` and `mv research/x.md projects/x.md` were denied, because SQ-65
judged every literal path under the state directory. SQ-76 had already let a
pattern go there unless the component in the state-file position could match
`canvas.md` or `decisions.md`. `namesAbsentStateDir` now applies the same rule
to literal words, comparing without case, since a case-blind volume puts
`research/Canvas.md` on the canvas. An opaque word follows the same rule in
`opaqueReachesState`: a word that reaches below a `research` component through
a literal tail is let go unless the first component of that tail can be a state
file. An unknown part anywhere in the tail counts as "can", because it can be
`canvas.md` or climb back with `..`. A spelled path to the directory itself
(`research/`, `./research`, `"$d/research"`) is still judged, because copying a
folder into it can bring the canvas along.

Still denied in a bare project: `cat > research/canvas.md`,
`git checkout HEAD -- research/`, `cp x.md "research/$f"`,
`git checkout HEAD -- research && cp x.md research/canva?.md`, `rm -rf
research/*`. Nothing changes in a project that holds state beyond the brace
and loop rows now being denied. The harness state directory, `accept` and the
environment-on-CLI refusal are unchanged everywhere.

`plugins/research-harness/test/guard-promotion.test.js` gains two SQ-75 tests.
The first covers the brace rows A plus `sed -i` and a sequence, as DENY rows in
a stateful project, with quoted and escaped braces and `find -exec {} +` as
ALLOW rows. The second covers the vault rows and the original report's loop as
ALLOW rows in a project with a notes-only `research/`, and the bare-project
DENY rows above plus loop, case and harness controls. No existing test was
changed.

**Spec, flagged, not edited.** §5.3 speaks of "a resolvable word that can
denote the state directory". A proposed sentence for the orchestrator to place:
"Where the state directory holds neither the canvas nor the decision log, a
word below it is judged only when the component where the state files stand is,
or can expand to, one of them; an unknown part in that position counts as one
that can."
