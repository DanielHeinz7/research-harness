New `research-harness doctor` command: one summary line, plus one line per
failed check, exit 0 only if everything holds. It checks that
`enabledPlugins` in the applicable settings files (user, project, local)
names and enables `research-harness@<marketplace>`; that
`hooks/guard-promotion.js` actually denies a model promoting a `[proposed]`
statement to `[accepted]` on a throwaway project, and allows an ordinary
read; and, inside a paper project, whether the sealing key `accept`/`log`
need is present. `doctor` is added to the guard's read-only CLI whitelist so
the model may run it itself. The README suggests running it first after
install, and notes it reads settings files rather than a running Claude Code
process's actual state.
