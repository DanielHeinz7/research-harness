---
ref: SQ-98
title: Session view URL carries a single-use code, not the write token
bump: patch
plugins:
  - research-harness
---

`research-harness serve` now prints and opens a URL with a single-use code (`#c=…`) instead of the write token. The view trades the code for the token once through `POST /api/session` and keeps the token in memory only; the code expires after 60 seconds, and a second exchange is refused until the server restarts. A copy of the URL in terminal scrollback, a process listing or browser history is dead once the view has loaded. The terminal prints `session code redeemed` with a timestamp, and a view that loses the race says the link was already used.
